# コードレビュー

対象: `$ARGUMENTS` で渡されたファイル。渡されなければ、直近に学習者が貼ったコードか、`git status` で変更されたファイル。

観点を順に確認し、以下の形式で返す。

1. **動くか**: 実際に `node` や `npm run` で実行して確かめる。実行できない場合はその理由を伝える。
2. **良い点**: 具体的に 1〜3 個。何が良いのかの理由を添える。
3. **直すべき点**: 1 つずつ「どこ・なぜ・どう直すと良いか」を書く。直したコードは書かず、修正方針と最小サンプルにとどめる。
4. **今週の学習項目との対応**: 使えているべき文法が使えているか。
5. **合格判定**: 合格なら commit メッセージを学習者に考えさせ、`PROGRESS.md` の更新を促す。不合格なら直す箇所を 1 つに絞って再提出を求める。

`CLAUDE.md` のルールに従い、完成コードは書かない。
